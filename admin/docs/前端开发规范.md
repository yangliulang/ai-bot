# TG-BOT-Admin 前端开发规范（Agent 协作版）

本文档用于 **指导人机协作下的前端工程实践**：默认约束 Agent 的实现路径与交付口径；团队在立项时可对本规范打补丁（见文末），锁定具体栈版本与目录脚手架。

---

## 1. 优先级与冲突处理

当多处约定不一致时，按下述顺序 **从高到低** 适用：

1. **用户在当前对话中的明确指令**（含当轮临时例外）。
2. **本仓库根目录 `agent.md`**（AI 默认职责与协作边界）。
3. **本文档 `docs/前端开发规范.md`**。
4. **业界惯例与框架默认行为**（仅在本文未覆盖时兜底）。

若用户指令要求偏离本文档，须在答复或 PR 说明中 **简短交代偏离原因与风险**，除非用户声明可省略。

---

## 2. 架构原则（强制）

- **高内聚、低耦合**：业务功能按 **领域 / 功能切片（feature）** 组织；跨切片依赖通过 **显式公共层**（`shared/`、`entities/`、`api/`）完成，禁止深层穿透导入。
- **单向数据流、清晰边界**：UI → 应用编排 → 领域逻辑 → 数据访问；避免在视图层直接拼装复杂业务规则。
- **契约优先**：对外接口（HTTP/WebSocket 等）先有 **请求/响应形状与错误模型**，再写页面；类型定义与后端契约 **同源或可校验**（OpenAPI、手写契约二选一，立项时定）。
- **可演进**：目录与模块边界允许重构，但 **公共 API（导出符号、路由路径、对外类型）变更须标注破坏性** 并集中迁移。
- **可观测与可维护**：关键用户路径与异常须有 **可定位日志或错误边界**（不向终端用户泄露敏感细节）。

---

## 3. 文件头与变更留痕（强制）

凡 **创建、修改** 可编辑源码或配置文件（如 `*.vue`、`*.ts`、`*.css`、路由与构建配置等），须在文件 **首部** 以注释注明 **作者**、**日期**、**修改功能**（新建文件写清意图即可），便于协作追溯与版本对照。

- **作者**：人机协同时可写可操作主体（例如 `杨永的Agent`），亦可为实际开发者姓名或账号。
- **日期**：建议 `YYYY-MM-DD`（或与团队统一格式），以 **本次变更合入当日** 为准。
- **修改功能**：一句话说明本次改动目的或范围。

**格式示例（三行，可改为块注释或 `<!-- -->` 等与语言一致的形式）：**

```text
作者: 杨永的Agent
日期: 2026-05-11
修改功能: 侧栏品牌区与图标对齐，仅展示「AI Agent 管理端」
```

- **新建文件**：须写全上述字段。
- **再次修改**：须更新 **日期** 与 **修改功能**；作者字段是否覆盖或追加「最后修改者」由团队约定。
- **Vue SFC**：注释放在 **`*.vue` 文件最顶部**（`<!-- -->`）或 **`<script setup>` 内首行块注释**，全仓择一保持一致。
- **例外**：第三方原样 vendor、仅机器生成且明确不入库的锁文件等；团队可再收窄豁免范围。

## 4. 推荐技术基线（Greenfield 默认）

从 0 立项时 **默认采用** 下列组合；若更换栈，须在仓库 `README` 与本文档 **§12 项目补丁** 中写明替代方案及对本文映射关系。

| 类别 | 默认选型 | 说明 |
|------|-----------|------|
| 语言 | TypeScript（`strict`） | 避免隐式 `any`；公共导出须有类型 |
| 框架 | Vue 3 + Composition API + `<script setup>` | 组件逻辑复用优先 `composables/` |
| 构建 | Vite | 环境变量遵循 `VITE_` 前缀约定 |
| 路由 | Vue Router | 路由元信息承载权限与布局 |
| 全局状态 | Pinia | 按域拆分 store；避免万能 store |
| HTTP | `fetch` 或封装的 `ky` / `axios`（立项定一） | 统一超时、错误解析、鉴权注入 |
| 校验 | Zod 或 Valibot（立项定一） | 用于运行时校验外部数据边界 |
| 样式 | Tailwind CSS 或 Scoped CSS + CSS 变量（立项定一） | 设计令牌优先变量化 |
| 代码风格 | ESLint + Prettier | 提交前可配合 lint-staged |
| 单元测试 | Vitest + Vue Test Utils | 核心业务与 composable 优先覆盖 |

**不强绑 UI 组件库**：选定后在本仓库统一（如 Naive UI / Element Plus / 自研），避免同一视图混用多套无令牌对齐的库。

## 5. 目录与分层约定（推荐脚手架）

下列结构为 **推荐默认**，可按业务减量但 **不得破坏分层语义**：

```text
src/
  app/                 # 应用壳：入口、全局插件、路由注册、根布局
  pages/               # 路由级页面（薄）：组装区块与数据注入
  widgets/             # 跨页复用的大型区块（可选）
  features/            # 业务功能切片（推荐主战场）
    <feature-name>/
      ui/              # 仅本功能使用的展示组件
      model/           # 状态、领域规则、用例编排（Composable / Service）
      api/             # 与服务端对话的适配层（若与其它 feature 共享则上移）
  entities/            # 业务实体与纯函数工具（无 UI）
  shared/
    api/               # 全局 HTTP 客户端、拦截器、错误类型
    config/            # 运行时配置、常量
    lib/               # 与业务无关的工具
    ui/                # 与设计系统一致的原子/通用组件
  assets/
```

**导入规则**：

- `features/*` 之间 **禁止** 任意交叉引用；共享逻辑须下至 `entities/` 或上至 `shared/`。
- `shared/` **禁止** 引用 `features/`、`pages/`。
- **路径别名** 在 `vite.config` 与 `tsconfig` 同步维护（如 `@/` → `src/`）。

## 6. 组件与组合逻辑

- **页面组件**：只做路由参数解析、布局占位、把数据传给 feature；避免巨石页面。
- **表单与选择控件**：文本、下拉、日期等须通过 `src/shared/ui` 已封装组件（如 `UiInput`、`UiSelect`、`UiButton`）实现，与全局 Tailwind 设计令牌一致；**避免在业务页直接使用未包装的原生** `<input>` / `<select>`（易与暗色主题分叉）。
- **展示组件**：props 入、events 出；避免在深层子组件读全局路由副作用（必要则用注入）。
- **Composable**：命名 `useXxx`；副作用（请求、订阅）须有 **取消/清理**；异步须有 **loading / error** 出口或可抛出边界。
- **性能**：大列表须 **虚拟化或分页**；重计算用 `computed` / memo；路由级代码分割为默认。

### 6.1 危险操作与 API 提交（强制）

与 `agent.md` 中的交互约定一致，实现时 **必须** 遵守：

1. **二次确认**  
   对 **危险或不可逆** 的用户意图须先确认再执行，包括但不限于：**退出登录**、**删除**、**清空**、**终局确认**、**批量不可逆操作** 等。  
   - **优先**使用 `src/shared/ui/UiModal.vue`（或等价无障碍对话框），提供明确标题、说明与「取消 / 确认」操作。  
   - **兜底**可用 `window.confirm`，但须在评审或 PR 中说明理由；默认不推荐。

2. **与 API 交互的提交类操作**  
   按钮或表单一旦触发 **出站请求**，须同时满足：  
   - **防重复触发**：请求进行期间忽略再次点击（或等价防抖）；推荐复用 `src/shared/lib/useAsyncAction.ts`，或在单一入口自行维护「进行中」锁。  
   - **加载反馈**：进行中对按钮使用 **`UiButton` 的 `loading` 属性**（内置禁用与可视指示，并配合 `aria-busy`）；禁止在 loading 时重复提交。  
   - 若业务为 **长时间任务**（分步/轮询），须在 §6「Composable」原则下补充 **error / 超时** 出口。

---

## 7. 状态管理

- **服务端状态**（列表、详情、分页）：优先 **请求层缓存 + 组件本地状态**；必要时再用 Pinia 跨页面共享。
- **客户端全局状态**（会话、主题、当前 Bot 上下文等）：Pinia **按域拆分**，禁止单文件巨型 store。
- **派生状态**：优先计算属性，避免重复存储同步字段。

---

## 8. API 与错误模型

- **统一响应解析**：约定业务错误码与 HTTP 状态分工；前端 **单一入口** 转成 `AppError`（或等价类型）。
- **鉴权**：Token / Cookie 刷新策略在 `shared/api` 一处实现；403/401 **统一跳转或弹窗**，不在每个请求散落处理。
- **类型**：DTO 类型与运行时校验 **至少具备其一**；对外部 JSON **不信任**，边界处校验。

---

## 9. 路由、权限与菜单

- **路由表为单一真相**：权限指令写在 `meta`（角色、能力键）；导航菜单 **由路由派生** 或独立配置但与路由对齐。
- **禁止**: 仅在前端隐藏高危按钮而无后端鉴权（前端只做体验优化；安全以后端为准）。

---

## 10. 安全基线

- **不得** 把密钥、Bot Token、数据库连接写入前端仓库或 `VITE_` 环境变量。
- **XSS**：慎用 `v-html`；必须使用时输入须经过明确的白名单或后端消毒。
- **依赖**：定期审计；禁止引入无维护记录的冷门包除非评审记录。

---

## 11. 质量门禁（建议落地为脚本）

- `typecheck`：`vue-tsc` / `tsc --noEmit`
- `lint`：ESLint（含 vue/ts 规则）
- `format`：Prettier（CI 或 pre-commit）
- `test`：Vitest；核心模块覆盖率阈值 **立项时拟定**

**Agent 交付口径**：凡改动逻辑或接口契约，须保证上述脚本 **在本仓库约定命令下可通过**（若仓库尚未初始化脚本，须在答复中列出待补命令）。

---

## 12. Git 与协作（默认）

- **分支**：功能分支 `feat/<topic>`，修复 `fix/<topic>`；合并策略（merge/rebase）立项时定。
- **提交信息**：动词开头、中英文均可，建议 Conventional Commits（`feat:`、`fix:`、`docs:`）。

---

## 13. 项目补丁（立项后填写）

以下为 **本项目锁定项**，随仓库演进更新：

| 项 | 本项目取值 |
|----|------------|
| UI 组件库 | **Reka UI**（无样式基元）+ **`src/shared/ui` 薄封装** + Tailwind；复杂表格可后续引入 **TanStack Table** 等，不另起第二套皮肤库 |
| HTTP 客户端 | **ky**（`src/shared/api/http-client.ts`） |
| 校验库 | **Zod** |
| 样式方案 | **Tailwind CSS v4**（`@import 'tailwindcss'`） |
| 后端契约来源 | **暂无**（接入后以 OpenAPI 或手写 DTO 为准） |
| Node / 包管理器版本 | **Node** `^20.19.0 \|\| >=22.12.0`；包管理器 **npm**（见仓库 `package-lock.json`） |

## 14. Agent 工作方式（执行 checklist）

接到开发任务时 **默认执行顺序**：

1. 阅读 `agent.md` 与本规范；确认 §13 锁定项是否已填。
2. 明确改动所属的 `feature` / `shared` 层级，避免破坏 §5 导入规则。
3. 创建或修改文件时遵守 **§3 文件头与变更留痕**。
4. **先契约与类型**，再 UI；接口变更同步文档或契约产物。
5. 小步提交：单一意图；附带必要测试或说明为何暂不测。
6. 自检：`typecheck` + `lint` +（若有）`test`。
7. 若涉及 **危险操作或 API 提交**，对照 **§6.1** 检查二次确认与 loading / 防重复触发。
